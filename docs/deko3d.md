# Рендерер на deko3d (план)

Зачем: на Switch нативный рендерер ds2-nx работает через Vulkan → NVK (Mesa, `G:\DS2Switch\mesa-switch`). На частотах
владельца кадр DS2 упирался в GPU: сцена 12–17 мс, копии 3.6 мс, резолвы ~3 мс (ds2-nx, записи 72–75). Копии и
резолвы — в полосу памяти; часть стоимости — драйвер: барьеры, переключения движков, раскладки изображений.
deko3d (devkitPro, тонкий слой над командами Maxwell) даёт прямое управление памятью, сжатием, барьерами и кэшами.
Выигрыш **не измерен** — первый этап плана именно замер.

## Что есть
- devkitPro: `G:\devkitPro\libnx\include\deko3d.h/.hpp`, `libnx\lib\libdeko3d.a` (+ отладочная `libdeko3dd.a`),
  компилятор шейдеров `tools\bin\uam.exe` 1.1.0 (GLSL → DKSH).
- Рендерер ds2-nx (`app/src/me/`): ~38 тыс. строк; прямые вызовы Vulkan — в основном `sa2_native_targets.cpp`
  (~360) и `sa2_native_draws.cpp` (~145), плюс `sa2_deferred_recording.cpp`, `sa2_shader_library.cpp`,
  `me_native_system.cpp`; 35 своих шейдеров (`app/src/me/native/shaders`, GLSL/compute → SPIR-V).
- Шейдеры игры: Xenos → (XenosRecomp) → HLSL → DXC → **SPIR-V** (пакет `sa2_shaders.mesp`). uam принимает GLSL,
  значит, нужен шаг SPIR-V → GLSL (SPIRV-Cross; в `sdk/thirdparty` его **нет**, есть spirv-tools/headers) или
  HLSL → GLSL напрямую. Выбор — открытый вопрос.

## Правила
- Отдельный бэкенд за ключом (например `renderer_backend = "vulkan" | "deko3d"`), Vulkan-путь не ломать.
- Сначала минимальный путь до картинки, потом перенос оптимизаций EDRAM. Каждый шаг — A/B с Vulkan на консоли
  (время GPU по категориям, fps, картинка).

## Этапы (предложение)
1. **Замер потолка.** Отдельный тестовый NRO на deko3d: полноэкранные копии 1280x720 (RGBA8, RGBA16F), compute
   «resolve bias», очистки — та же нагрузка, что у ds2-nx на кадр. Сравнить с NVK (ds2-nx: копии ~0.5 мс/Мпикс,
   bias ~0.42 мс на 1280x720). Если выигрыша нет — пересмотреть план.
2. **Конвейер шейдеров.** SPIR-V → GLSL → uam → DKSH для пакета шейдеров и своих 35 шейдеров; кэш DKSH на SD.
3. **Минимальный бэкенд.** Устройство, очередь, swapchain/показ, память (кучи deko3d), изображения, отрисовка
   без EDRAM-оптимизаций (как `sa2_native_edram_alias_mode` по умолчанию в sa2-nx).
4. **EDRAM mode 4 и резолвы** — перенос логики владения тайлами, импортов/экспортов, резолвов.
5. **Оптимизации deko3d**: сжатие цветовых целей, барьеры только по нужным стадиям, копии через 2D-движок,
   меньше переключений 3D/compute.

## Открытые вопросы
- Где проходит граница абстракции: переписать вызовы Vulkan в `sa2_native_*` за интерфейсом или отдельные файлы
  `dk_native_*` с общей логикой EDRAM.
- SPIRV-Cross (добавить в thirdparty) или прямой HLSL → GLSL.
- Как совмещать с PC-сборкой (deko3d только на Switch; на PC остаётся Vulkan).

# DS2 SotFS HOME forwarder

Выбранный владельцем вариант: отдельный NSP-forwarder по образцу Prototype 2,
с запуском существующего `sdmc:/switch/ds2scholar-nx/ds2.nro`, 39-bit и
разрешением процесса на ядра0–3. Альтернатива с кодом игры внутри NSP не нужна:
она не даёт дополнительных CPU-разрешений и усложняет обновления.

Собирается только загрузчик. NRO, конфиг, игровые данные, сохранения и системный
`atmosphere/hbl.nsp` не меняются. Core3 разрешается NPDM, но настройка масок
потоков и заявления о приросте производительности требуют отдельного A/B.

Мои технические решения: Title ID `01445332534F0000` (01+DS2SO+0000), имя/иконка/
версия из проверенного NRO; StartupUserAccount=Required для выбора пользователя
HOME. Ключи читаются только локально, не выводятся и не входят в пакет/Git.
Исходники Forwarder-Mod и hacBrewPack закреплены на коммитах из Prototype 2.

Инструмент Python подготавливает metadata и проверяет полученный NPDM
(ACI0+ACID, ядра0–3, 39-bit, Title ID), NACP и путь NRO. Сборка использует
установленные devkitA64/libnx и MSYS2; Docker/WSL не установлены.
Все результаты — в ignored out/. Forwarder сопровождается лицензией загрузчика,
инструкцией и SHA256. Загрузка готового NSP на SD — через FTP с --backup;
установка и запуск с HOME проверяются отдельно на консоли.

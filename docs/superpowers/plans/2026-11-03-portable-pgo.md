# Переносимый PGO v4 — план

> Исполнение: superpowers:executing-plans; один итоговый reviewer.

**Цель:** отдельный ZIP существующего PGO v4, установка в другой каталог
репозитория и проверка реального применения GCC. Пакет не публикуется автоматически.

**Решение:** Python stdlib, ZIP с manifest.json и 364 GCDA; SHA256 каждого
файла, версия GCC и совместимый source commit. Четыре имени с абсолютным
корнем заменяются при экспорте токеном, при установке — корнем пользователя.
Содержимое GCDA не меняется. Raw stream с путями владельца не распространяется.
Установщик отказывает при несовместимых исходниках/компиляторе, испорченном
пакете и непустом pgo/. Игровые данные и generated-код в ZIP не входят.

**Файлы:** tools/pgo_bundle.py (pack/install), tools/tests/test_pgo_bundle.py,
tools/pgo_fit.py (выбор build-dir для проверки), docs/pgo-profile.md,
docs/workflow.md, docs/progress.md; артефакты только out/.

**Ограничения:** исходный pgo/ неизменен; отдельная экспериментальная ветка;
проверочный клон out/clean-clone-20261103, Windows/devkitA64 GCC16.1.0.
Рендерер/настройки по умолчанию/консоль не меняются.

## Проверки и шаги

- [x] Тесты до реализации: round-trip двух корней с пробелами, контрольные
  суммы и неизменность GCDA, отказ при повреждении/повторе имён/версии GCC,
  конфликте pgo/ и выходе пути за каталог. Запуск unittest: ожидаемый FAIL.
- [x] Реализовать pack/install и получить PASS; проверить перенос исходников
  относительно записанного commit, без привязки к ветке пользователя.
- [x] Добавить --build-dir в pgo_fit.py; собрать ZIP и установить в клон.
- [x] Проверить перенесённые профили компилятором с включёнными предупреждениями:
  сначала контрольные объекты, затем все игровые объекты и четыре абсолютных
  объекта. Потери профиля считать отдельно от успешной компиляции; при ошибке
  исследовать причину, не отключать диагностику ради зелёного результата.
- [x] Записать фактический охват/ограничения, SHA256 ZIP и команды; итоговое
  независимое ревью, журнал и коммит. Сам ZIP и GCDA не коммитить.

## Риски для ревью

Абсолютные имена объекта CMake; источник с другим корнем и пробелами;
устаревшие CFG-checksum; другое семейство GCOV; обновление поверх своих профилей.
Каждый риск покрывается тестом либо настоящим GCC-прогоном.

## Журнал решений

Ruling: пакет также содержит codegen.partition.json и устанавливает его перед
кодогеном с бэкапом прежнего sidecar. Причина: свежий кодоген не имеет старого
распределения функций; sub_83391DE0 перешла из recomp.258 в recomp.0, и все
293 гостевые функции пробного файла остались без своих записей. Контрольный
прогон в исходной папке:325 функций,0 потерь. Простое переименование четырёх
GCDA недостаточно. Счётчики и CFG-checksum не переписываются; C++ из игры
в архив не входит. После установки sidecar необходим повторный кодоген.

Ruling: диагностика различает отсутствующий GCDA и отсутствующую функцию
в найденном GCDA (оба GCC помечает Wmissing-profile). Тесты закрепляют различие.
Также аргументы Ninja на Windows разбираются CommandLineToArgvW: прежний
shlex оставлял обратные слеши в строковых макросах REXGLUE_BUILD_CONFIG.

Ruling: полный прогон366 объектов выполнен один раз. Его exit1 сохранён:
классификатор счёл3 аргумента шаблонов Draw<__imp__sub_…> гостевыми именами.
Регрессионный тест RED→GREEN уточнил имя функции наличием следующей `(`;
все сохранённые GCC stderr повторно разобраны новым кодом,exit0. Перекомпиляция
не нужна при неизменных C++ и флагах; отдельная проба с путями с пробелами
скомпилирована после поправки,exit0. В полном отчёте1179 отсутствующих
вспомогательных профилей и3 mismatch Start/DumpNow/Stop сохранены отдельно.
Итоговое ревью подтвердило обоснованность поправки и границы проверки.

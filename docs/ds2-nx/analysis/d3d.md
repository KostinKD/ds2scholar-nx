# Direct3D-функции XDK в Default.xex (этап 4)

Нужны нативному рендереру (`app/src/me`, из sa2-nx): хуки `Draw*`, загрузки шейдеров при отрисовке, сброса
констант и регистров, flip; смещения привязанных VS/PS в device.

## Как искали

`tools/d3d_match.py` сравнивает функции с игрой, где они уже названы, но на этой машине нет ни одного эталонного
образа или сгенерированного дерева: sa2-nx и nfsmw-nx игровых данных не хранят, а sa2 сама сопоставлялась с
Banjo-Kazooie. Поэтому функции найдены по их собственным признакам, `tools/d3d_find.py`:

- `callers <addr>` — вызывающие (`bl`);
- `const <value>` — функции, собирающие 32-битную константу через `lis` + `ori`/`addi`;
- `draws` — функции, собирающие PM4-заголовок `DRAW_INDX` (0x22) / `DRAW_INDX_2` (0x36).

Сверка с sa2 — по таблице в `G:\DS2Switch\sa2-nx\docs\sa2-notes.md` («Named D3D functions») и
`sa2-nx/app/src/me/sa2_me_hooks.cpp`.

## Найдено

| Функция | ds2 | sa2 | Доказательство |
|---|---|---|---|
| `D3DDevice_Swap` | `sub_829BB520` | `sub_82558E98` | единственный вызывающий импорта `VdSwap` (thunk 0x83402004), вызов на 0x829BB8A8 |
| flip (кадр в обработчике прерываний) | `sub_829BA620` | `sub_82557FC0` | вызывается из обработчика прерываний GPU `sub_829A7F70` (`SetInterruptCallback(829A7F70, …)` в логе), пишет `D1GRPH_PRIMARY_SURFACE_ADDRESS` (0x6110) |
| настройка дисплея | `sub_829BA750` | `sub_825580F0` | тоже пишет 0x6110, рядом с flip |
| `D3DDevice_DrawVertices` | `sub_829C2E28` | `sub_82565C60` | `DRAW_INDX` (`ori …,0x2201` ×2), FlushState-цепочка; сохраняет r4–r6 = (dev, type, start, count); указатель в vtable графического слоя движка (обёртка `sub_82EFC1D0`, указатель 0x8210461C) |
| `D3DDevice_DrawIndexedVertices` | `sub_829C3240` | `sub_82566078` | то же, но сохраняет r4–r7 = (dev, type, base, start, count); обёртка `sub_82EFC250` (указатель 0x82104628) |
| `D3DDevice_BeginVertices` | `sub_829C2340` | — | `DRAW_INDX`, FlushState; возвращает место в командном буфере |
| `D3DDevice_DrawVerticesUP` | `sub_829C2800` | `sub_82565C18` | вызывает `sub_829C2340`, затем `memcpy` (0x82FB7240) count×stride байт из r6 |
| `D3DDevice_BeginIndexedVertices` | `sub_829C2848` | — | как `BeginVertices`, с индексами |
| `D3DDevice_DrawIndexedVerticesUP` | `sub_829C2D88` | — | вызывает `sub_829C2848`, затем два `memcpy` (вершины, индексы 16/32 бит) |
| загрузка шейдеров при отрисовке (часть FlushState) | `sub_829BF328` | `sub_82556A60` | вызывается из всех Draw*/Begin*; читает device **+13072 (0x3310) = VS, +13068 (0x330C) = PS** — те же смещения, что у sa2 |
| сброс шейдерных констант | `sub_829BE590` | `sub_82555CC8` | дважды на Draw: r5 = 0x4000 (VS) с тенью device+1920, r5 = 0x4400 (PS) с тенью +6016 |
| сброс fetch-констант | `sub_829BE438` | `sub_82555B70` | константы 0x4800 и 0x5000 (как у sa2: «с 0x4800, затем пакет 0x5000») |
| группы регистров | `sub_829BE1F8` | `sub_82555930` | ~10 раз на Draw, r5 = 0x2000, 0x2100, 0x2180, 0x2200, 0x2280, 0x2300, 0x2380, 0x4900 |

Порядок вызовов в каждом Draw/Begin одинаков: `829BE590` ×2 → `829BF328` → `829BDE68` → `829BE1F8`… →
`829BE438` → … → `829BE2B8` → … → `829B9F08` → `829A9618` → `829A8F48`.

Смещения VS/PS в device у DS2 (XDK 2.0.21256) совпадают с sa2 (+0x3310 / +0x330C), то есть
`SetDeviceShaderOffsets` рендерера можно оставить как у sa2. Не проверено: остальные поля device, которые читает
рендерер.

## Проверка в рантайме (2026-10-16)

`app/src/ds2_d3d_census.cpp`: сильные `sub_X` подменяют слабые псевдонимы генератора, считают вызовы и вызывают
`__imp__sub_X`; cvar `ds2_d3d_census_s` (лог раз в N s). Прогон: лесной сейв владельца, меню → загрузка → бег →
удар (лог ds2 в out/pc/logs, 22:15–22:17).

| Функция | Меню | Лес | Вывод |
|---|---|---|---|
| Swap / flip / дисплей | 60/s | 60/s | ✓ |
| DrawIndexedVertices `829C3240` | 0 | 24–27 тыс./s (~420 за кадр) | ✓ основной путь |
| BeginVertices = DrawVerticesUP `829C2340`/`829C2800` | 1,5–2,3 тыс./s | 5,5–6,4 тыс./s | ✓ (UI) |
| BeginIndexedVertices = DrawIndexedVerticesUP | 0 | 180–260/s | ✓ |
| DrawVertices `829C2E28` | 0 | 0 | игра не вызывает (или адрес неверен — не доказано) |
| загрузка шейдеров `829BF328` | 300/s | ~18 тыс./s | ✓ |
| сброс констант / fetch / групп | на каждый Draw | 53–58 / 25 / 71 тыс./s | ✓ |
| `829CBAE8` (`DRAW_INDX_2` + предикат) | 60/s | 1,4–1,5 тыс./s | раз за кадр в меню — кандидат в Clear |
| `829AC6C0`, `829AC818`, `829B0E48`, `829C3E88`, `829CB130` | 0 | 0 | не вызываются |

Поля device в загрузке шейдеров: VS по +0x3310 — всегда ненулевой и ≥ 0x30000000 (≈ 200 тыс. вызовов); PS по +0x330C
нулевой только в игре (≈ 20 тыс. за 5 s) — проходы без пиксельного шейдера (глубина/тени); «плохих» указателей 0.
**Смещения VS/PS подтверждены.**

## Не найдено / отложено

- **`CreateVertexShader` / `CreatePixelShader`.** Магию контейнера (`0x102A1101`/`0x102A1100`) код не проверяет:
  `lis`+`ori` 0x102A1101 — 0 мест, 0x102A1100 — 7 функций движка, `xoris 0x102A` + `cmplwi` — 0. В рендерере эти
  хуки нужны только для выгрузки контейнеров шейдеров в пакет; у DS2 шейдеры лежат в файлах (`.fxo`, шейдерные
  BND4 `shader/*.bnd`, плюс внутри GameData), пакет можно собрать из них.
- **`D3DDevice_Clear`, `D3DDevice_Resolve`.** Кандидаты — функции с `DRAW_INDX_2` (`0xC0003600`, отрисовка
  прямоугольников): `sub_829AC6C0`, `sub_829AC818`, `sub_829B0E48`, `sub_829C3E88`, и с `0x3601`: `sub_829CB130`,
  `sub_829CBAE8`. Не разобраны.
- `sub_829BDE68` (читает device +13084/+13088/+13104/+13108) и `sub_829BE2B8` — назначение не установлено.

# Запуск с HOME и четвёртое ядро — проверка 2026-11-05

Вывод для DS2 SotFS: предпочтителен отдельный NSP-forwarder с собственным
NPDM, ядрами 0–3 и 39-битным адресным пространством. NRO остаётся на SD;
доступ к core3 сам по себе не требует помещения исполняемого кода игры в NSP.
Это рекомендация по результатам чтения исходников, не проверенная сборка DS2.

## Проверенные локальные примеры

- `G:/DS2Switch/prototype2-nx/tools/build_forwarder.sh`: Forwarder-Mod и
  hacBrewPack закреплены на коммитах. Скрипт задаёт lowest/highest CPU 0/3,
  address_space_type=3; проверяет обе таблицы ACI0/ACID готового NPDM.
  NSP запускает `sdmc:/switch/Prototype2/prototype2.nro`. Четвёртое ядро
  также включено в маски потоков в config/prototype2.toml; описание в
  docs/FOURTH_CORE.ru.md. Заменять глобальный atmosphere/hbl.nsp не требуется.
- `G:/DS2Switch/nfsmw-nx/README.md`: запуск через title override либо forwarder;
  для последнего явно требуется 39-bit. README предлагает Sphaira.
- `G:/DS2Switch/sa2-nx/README.md`: title override либо forwarder с 39-bit.
- `G:/DS2Switch/ds2-nx/docs/progress.md`: вариант четвёртого ядра через
  NSP-forwarder 0–3 как в Prototype 2 рассмотрен, но отложен; приведённый
  там CPU около230% из300% относится к прежней DS2 и не доказывает нагрузку SotFS.

## Источники и ограничения

Текущий [nx-hbloader hbl.json](https://github.com/switchbrew/nx-hbloader/blob/master/hbl.json)
ограничивает highest_cpu_id значением2. В
[заметках v2.0.0](https://github.com/switchbrew/nx-hbloader/releases/tag/v2.0.0)
указана историческая причина исключения core3: стабильность потоков и балансировки.
Четвёртое ядро используется также системными службами; оно не становится
выделенным ядром игры. Прирост FPS и стабильность требуют A/B на консоли.

Последний скачанный профиль DS2 (`out/switch_logs/latest/rex/rex_profile.log`,
сеанс 05.11 14:17–14:18) содержит `process cores 3 (mask 0x7)`.
CPU1785/GPU921,6/память2133МГц. Доступа к четвёртому ядру в этом сеансе нет.

Одного разрешения NPDM недостаточно, если конкретный поток ограничен маской:
в `app/src/me/native/sa2_deferred_recording.cpp` worker использует0x7;
`ApplyExclusiveCore` в sdk/src/ui/switch_perf.cpp принимает только ядра0–2.
Перед использованием core3 надо отдельно проверить фактические маски
и распределение потоков; производственные настройки в этом исследовании не менялись.

Самостоятельный NSP может иметь такие же разрешения процесса, но потребует
отдельной упаковки/обновления исполняемого кода. Преимущества по CPU только
из-за помещения кода внутрь NSP найденные примеры не показывают.

Не выполнялись: сборка/установка forwarder для DS2, изменение NRO/TOML,
замена системного загрузчика, замеры четырёх ядер. Следующий шаг при реализации:
отдельный эксперимент и A/B одной сборки с доступом0–2/0–3, с проверкой HOME,
сна, выбора пользователя, сохранений и онлайна.

# GPU: шейдеры и B10G11R11 — эксперимент 2026-10-25

Ветка `perf-shader-lite-r11`. Исходное поведение сохранено по умолчанию.
Новые варианты меняют качество; их нельзя включать в основной конфиг до консольного A/B и оценки картинки владельцем.

## Шейдеры

Номера подтверждены по `ds2_049.log` / `ds2_075.log`; выбор выполняется по хешу всего контейнера.
Варианты в одном пакете, SpecId 0 bit 23, ключ `ds2_shader_light_mask` по умолчанию 0.
Маска меняется раз в кадр; бит специализации входит в PipelineKey и сохранённые записи прогрева.
Со старым пакетом без варианта — предупреждение и исходный шейдер.

| Маска | Хеш / номер в v8 | Что упрощается | Инструкции SPIR-V off → on | Выборки off → on |
|---:|---|---|---:|---:|
| 1 | `04762adf6a086695` / PS31 | Один кадр частицы без flipbook-интерполяции | 1134 → 945 | 2 → 1 |
| 2 | `3c14b756c88a2b7f` / PS385 | Последняя степенная кривая тумана заменена линейной; расстояние/высота сохранены | 2247 → 2221 | 6 → 6 |
| 4 | `41db93b1dec497de` / PS421 | Умножение цвета частицы вместо overlay; альфа и последующее освещение сохранены | 939 → 899 | 1 → 1 |
| 8 | `9942495d3b412155` / PS961 | Первый слой diffuse/bump/specular без второго слоя и blend-map | 3662 → 3052 | 11 → 7 |

Это число инструкций промежуточного представления, включая объявления, а не машинных инструкций GPU
или обещание прироста fps. В логах время относится ко всему проходу по его первой отрисовке.
Вариант PS385 имеет небольшой статический выигрыш, а кривая тумана может измениться заметно.
PS961 меняет внешний вид смешанных поверхностей; PS31 — плавность анимации частиц;
PS421 — их цвет. Проверять по одному биту.

Простой нулевой вес второго слоя PS961 не удалил выборки в DXC (NaN * 0): поэтому выборки
дополнительно отключаются в облегчённой ветви. В исходной ветви все выражения сохранены.

Воспроизведение (через `tools/win/run.ps1`, после настройки SA2_LLVM/SA2_VSDIR):

```text
python -m unittest discover -s tools -p test_ds2_shader_light.py
clang++ -std=c++20 shaders/tests/test_ds2_shader_light.cpp -o out/test_ds2_shader_light.exe
python tools/ds2_shader_light.py --output out/shader_light_<новое_имя>
```

Преобразователь сверяет SHA-256 входных HLSL, требует ровно по одному ожидаемому месту правки,
компилирует original / forced-off / forced-on / specialization для каждого из 4 шейдеров.
Forced-off имеет тот же гистограммный состав инструкций, что original; это статическая проверка,
она не заменяет runtime A/B. Пакет собирается через `--replace-exact` поверх сохранённого v8:
1591 контейнер, заменены только 4. Игровые HLSL/SPIR-V/бинарники — только в out, не в git.

Проверенный пакет: `out/shader_light_final/sa2_shaders.mesp` (73 442 292 байта) и `.idx`
(3 258 528 байт). Отчёт DXC — `out/shader_light_final/report.json`.

## B10G11R11 — отдельный A/B

Используется существующий `ds2_7e3_r11g11b10`, по умолчанию false. Добавлен недостающий
экспорт глубины в этот формат; остальные пути формата сохранены.
Предыдущая консольная пара ds2_066/067 в Маджуле: занятость GPU 31,7 → 31,1 мс (~2 %),
картинка одобрена владельцем; лес ds2_065 был с другим видом и не является A/B.

Новый PC-прогон до правки (ds2_092): R11 `YES (features 0001DD83)`, 244 с без падения,
но depth→color base0 не поддерживался: 8 сообщений (дальнейшие подавляются), depth exports
3000/10s против baseline3322/10s. Режим `banjo_native_edram4_skip_unsupported` помечал тайлы
синхронизированными без переноса. Поэтому такой замер не доказывает ускорение при равной работе.

Причина — выбор pipeline в `ConvertDepthEDRAM4`: RGBA8/RGBA16F/raw64, без B10G11R11.
Добавлен вариант существующего `me_edram_depth_to_16f.comp` с `DST_FMT=r11f_g11f_b10f`,
pipeline4 создаётся только при активном поддержанном R11; индексы0..3 сохранены. Тест реального
GLSL подтверждает формат хранения2/8 (RED→GREEN). Повторный runtime ds2_093: 244 с,
0 skipped, 0 guest AV, depth exports3322/10s и transferred37552 — ровно как у baseline
в устойчивом окне. Снимок `out/gpu_lite_pc_ab/r11_fixed.png` без явных повреждений;
это не побитовая проверка картинки. Прежние ~2 % нужно перемерить после правки экспорта.

Подготовлены конфиги в `out/gpu_ab`: `00_baseline.toml`, `01_particles.toml`, `02_fog.toml`,
`03_debris.toml`, `04_material.toml`, `06_r11.toml`. Везде фиксированные 720p, динамическое
разрешение и ограничение 30 fps выключены; каждый конфиг меняет только свой эксперимент.
Для r11 маска шейдеров 0; для шейдеров r11 выключен.

Консольный замер: один неподвижный вид в лесу/тумане, одинаковые частоты, после прогрева
по 60–90 с baseline / r11 / baseline. Сверять реальное GPU-время, количество отрисовок,
частоты и картинку; отдельно повторить разрушение предметов для маски 4.
Нельзя складывать выигрыши шейдеров и формата по разным видам.

  явных повреждений изображения при осмотре нет. PS421 в этом виде не встретился.

  отдельный детектор обеих форм (старый generic detector не изменён), regression RED→GREEN
  и проверка по всем 4 реальным SPIR-V. До исправления mask=15 давал fallback.
- Один пробный запуск до исправления детектора упал с guest AV `sub_82F37B60`, чтение через
  нулевой указатель объекта перед виртуальным вызовом (PDB: `ds2_recomp.256.cpp:25586`).
  Причина не установлена; пропуск вызова/доступа не добавлялся. Повторный запуск прошёл 244 с.
- PC-тест B10G11R11 до исправления прошёл 244 с, на снимке явных повреждений нет;
  это не количественная сверка картинки (различаются поза/камера). Повтор после depth-export
  правки прошёл 244 с (см. выше).
- Switch собран: optimised+LTO+PGO, прежний профиль, 5 LTRANS jobs. Проверка относительно
  `sotfs_spike2.elf`: все проверки пройдены, `_start=0`, Mesa26.2.1/git1a8c1a66d6 совпадает
  с SDK, 1 известная гостевая остановка, vector FMA6 (как у эталона), новых нет.
  Есть прежнее предупреждение GCC в VertexFetchReorderAgreesWithPlacements
  (такое же в `logs/build_pgouse_sotfs.log`); этот код не менялся.
- Независимое ревью: блокирующих замечаний нет. Прогрев может держать обе специализации
  после A/B, что увеличивает время/память прогрева; неправильный вариант не подставляется.
- FTP 192.168.1.76:5000 в начале и конце сессии: timeout8s; консоль не менялась.

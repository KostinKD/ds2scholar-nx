# Повторная Switch-сборка — план

Цель: один Windows-вход `tools/win/rebuild_switch.ps1`, по умолчанию PGO use,
LTO и5 задач. Пользователь уже имеет инструменты, свою игру и установленный PGO;
консоль и значения игровых настроек не меняются.

- [x] Тестами закрепить отсутствие скрытого fallback без PGO, ограничение5 задач,
  очистку при изменении GCDA и пропуск кодогена при неизменных входах.
- [x] Python-драйвер запускает инструменты через argv без shell; PowerShell-вход
  вызывает его через run.ps1 с полным логом. Первый запуск/смена входов кодогена
  готовит host-генератор, glslang и кодоген; штатный повтор использует кэш.
  Профили и кодоген имеют отдельные SHA256-состояния. Конфигурация меняется
  при необходимости; успешные проверки кешируются по проверенным входам.
- [x] Перед первым clean сохранить прежние ELF/NRO в out/rebuild-backups;
  исходный pgo/ не менять. Без clean при изменившемся профиле собирать нельзя.
- [x] Настоящая сборка PGO NRO и повтор без изменений; проверка итогового NRO.
- [x] Короткая инструкция, независимое ревью, журнал/коммит; по уже полученному
  поручению владельца влить проверенную ветку в master и проверить тесты там.

Контроль: существующие41 unittest; новые тесты драйвера; Plan без изменений
файлов; логи сборки и проверки. Новые tools/rebuild_switch.py и Windows-вход
исключены из проверки исходников PGO как средства оркестрации без изменения C++.

Результат:56 тестов,366 объектов/84296 игровых функций с нулевыми потерями
игровых профилей. Повтор8,3с без работы Ninja. Доказательства и одноразовое
дополнение контекста кеша прототипа — в docs/progress.md за2026-11-03.
Два Important ревью закрыты: полный охват входов кодогена и запрет частичного PGO.
Финальное ревью разрешает слияние; minor про SHA анализатора записан в журнал.

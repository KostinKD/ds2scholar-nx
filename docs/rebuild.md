# Повторная сборка Switch

Используйте полный Git-клон с историей исходной ревизии профиля PGO.
Source ZIP — снимок файлов; без Git-истории установщик не проверит профиль.

После первоначальной настройки запускайте из корня репозитория:

```powershell
tools/win/rebuild_switch.ps1
```

Результат — `out/nx_pgo/ds2.nro`. По умолчанию включены **PGO use, LTO и 5 задач**.
Полный лог сохраняется в `logs/rebuild_switch_YYYYMMDD_HHMMSS.log`.

Один раз подготовьте зависимости по [clean-build.md](clean-build.md), собственную
Xbox 360 SotFS в `assets/game_root` и установите [пакет PGO](pgo-profile.md)
**перед кодогеном**. Нужен devkitA64 GCC 16.1.0. Игровые данные, PGO и результаты
сборки в Git не входят; ZIP профиля распространяется отдельно.

На машине владельца подхватываются LLVM и Visual Studio из `G:/Program Files`,
devkitPro из `G:/devkitPro`. На другой машине задайте `SA2_LLVM`, `SA2_VSDIR`,
`DEVKITPRO` и `NVK_SDK` по workflow. Остальные требования остаются прежними.

При первом запуске инструмент собирает host-генератор и glslang, запускает
optimised-кодоген с исходной таблицей распределения PGO и собирает Switch.
Изменение входов кодогена вызывает повторную генерацию. При смене GCDA прежние
ELF/NRO сохраняются в `out/rebuild-backups`, затем выполняется clean.
Неполный или несовместимый профиль завершает команду ошибкой.

После изменения входов выполняется реальная проверка GCC по всем объектам
(`pgo_fit --all --strict-guest`). Она требует отсутствия потерь игровых профилей;
служебные функции проверяются отдельно в отчёте `out/pgo_fit/nx_pgo/report.json`.
Затем проверяются ELF/NRO. Успешные проверки кешируются по входам, правилам Ninja,
состоянию игровых объектов и хешам бинарников, проверяющего скрипта и libvulkan.
При неизменных входах повтор использует кеш. CMake вызывается заново только при
необходимости: лишняя конфигурация меняет SDK BUILD_TIMESTAMP и вызывает LTO-ссылку.

Известное ограничение кеша:изменение самого `tools/pgo_fit.py` пока не входит
в его ключ. После правки анализатора запустите с `-Regenerate`,чтобы повторить
проверку;в этой подготовке анализатор не изменялся.

Дополнительные команды:

```powershell
tools/win/rebuild_switch.ps1 -Plan          # Только план и проверка входов
tools/win/rebuild_switch.ps1 -Clean         # Сохранить ELF/NRO и очистить сборку
tools/win/rebuild_switch.ps1 -Regenerate    # Принудительно повторить кодоген
tools/win/rebuild_switch.ps1 -Jobs 3        # Допустимо от 1 до 5
```

`-BuildDir out/другая_папка` и `-PgoDir pgo` меняют каталоги внутри репозитория.
При аварийном завершении может остаться `rebuild.lock`; перед его удалением
убедитесь, что предыдущий процесс завершён. Смену профиля выполняйте установщиком,
сохраняющим его таблицу распределения, а не ручной подменой отдельных GCDA.

# ds2scholar-nx — порт Dark Souls II: Scholar of the First Sin (Xbox 360) на Switch через ReXGlue

Общие правила для всех агентов (Codex читает этот файл, Claude Code — через CLAUDE.md). Проект начат 2026-10-21
копией рабочего порта **ds2-nx** (обычная DS2, Xbox 360 TU0): SDK, рендерер, инструменты и уроки перенесены, факты
об исполняемом файле — нет. Новая цель — та же игра в издании SotFS и второй рендерер на **deko3d**.

## Сборка и тесты
- Всё через `tools/win/run.ps1 <лог> "<команда>"` (пишет полный лог в logs/)
- Окружение: `. tools\win\env.ps1`. На этой машине дефолтные пути не подходят, перед вызовом:
  `$env:SA2_LLVM='G:\Program Files\LLVM'; $env:SA2_VSDIR='G:\Program Files\VisualStudio'`
  (clang 20.1.8; cmake 4.3.1 и ninja 1.13.2 из VS 2026 Community; MSVC 14.51, WinSDK 10.0.26100; Python 3.12.10)
- Кодоген: `tools/codegen.ps1` (вход — `assets\game_root\default.xex`)
- PC: `cmake --build out/pc --target ds2`; Switch: `tools\win\build_switch.ps1 -Jobs 5` (8 задач — нехватка памяти
  у cc1plus); полная Switch-сборка ~1 ч, LTO-ссылка ~20–35 мин
- Проверка NRO: `python tools/check_switch_build.py --sdk-vulkan <libvulkan.a> [--reference-elf <проверенный ELF>]`
- Тест-запуск: `tools/win/boot_test.ps1` — всегда muted+minimized; A/B рендерера на PC — `tools/win/native_ab.ps1`
  (ключи в `-Runs` разделяются `;`, варианты — `|`); подробности — docs/workflow.md
- Логи читать хвостом/grep, не целиком

## Правила
- `app/generated/` огромный: только grep по адресу функции, не читать файлами
- Каждая запись в манифесте/overrides — с доказательством (адрес, кто вызывает, почему)
- **Любой адрес, перенесённый из ds2-nx, считается неверным, пока не найден в SotFS заново** (по сигнатуре байтов,
  строкам, вызывающим) и не записан с доказательством. Список файлов с адресами DS2 — docs/porting-from-ds2.md
- Одно изменение за раз, каждое за своим ключом в конфиге (cvar), по умолчанию — прежнее поведение; включать по
  умолчанию только после A/B на консоли и проверки картинки владельцем
- Не говорить «исправлено» без запуска; писать, что НЕ проверено
- Перед работой прочитать docs/progress.md; в конце сессии — запись в журнал (дата — сделано — не проверено —
  следующий шаг) и коммит
- Игровые данные, сгенерированный код и бинарники не коммитятся (.gitignore)
- Рендерер deko3d — отдельный бэкенд за своим ключом; Vulkan/NVK-путь должен продолжать собираться и работать
  (docs/deko3d.md)
- Новая ветка для каждого эксперимента; в основную — после проверки
- Владелец пишет по-русски; отвечать по-русски, коротко, с цифрами из логов

## Логи с консоли

Если задача требует актуальных логов Switch, следуй инструкции [docs/switch-logs.md](docs/switch-logs.md): самостоятельно скачай логи с FTP перед анализом. Не проси владельца запускать сборщик вручную или копировать файлы. Если FTP недоступен, сообщи ошибку и используй существующие локальные данные.

Сборки (NRO, ds2.toml, пакет шейдеров) на консоль тоже загружай сам по тому же FTP: `tools/switch_upload.py`
(см. docs/switch-logs.md); не проси владельца копировать файлы на SD. Заменяемый файл сохраняй через `--backup`
и в отчёте пиши, что именно лежит на консоли (метка в hbmenu, ключи конфига).

# Трансляция (этап 2)

Манифест — `app/ds2_manifest.toml` (проект `ds2`, без `[[modules]]`, см. [xex.md](xex.md)). Ручные правки —
`app/overrides.toml`, у каждой записи есть доказательство. Кодоген — `tools/codegen.ps1` (classic), лог —
`out/codegen.log`, логи прогонов — `logs/codegen_run*.log`.

Адреса ниже взяты из образа, который генератор сбрасывает в `out/default_image.bin` (`REXGLUE_DUMP_IMAGE`).
Дизассемблировано через `tools/ppc_mini.py`.

## Генератор

`cmake -S sdk -B out/host -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_FLAGS=-march=x86-64-v2
-DCMAKE_CXX_FLAGS=-march=x86-64-v2`, затем `cmake --build out/host --target rexglue`. Бинарник:
`sdk/out/win-amd64/rexglue.exe`. Без `-march=x86-64-v2` (его задаёт пресет `windows-base` SDK, а в
porting-guide sa2 его нет) сборка падает на `sdk/src/core/memory.cpp:70` (`_mm_shuffle_epi8` требует ssse3).

## setjmp / longjmp

Найдены по форме: функция, которая сохраняет f14–f31 и r13–r31 по r3, и её зеркальная пара. В `.pdata` их нет,
поэтому искал окнами по `.text`.

| | Адрес | Форма | Прямых вызовов |
|---|---|---|---|
| setjmp | 0x82FB8A30–0x82FB8CF8 | hook-проверка (`lwz r0,0x836439D8; bnectr`), `mflr`/`mfcr`, `stfd f14–f31 @0..136(r3)`, `std r13–r31 @152..296(r3)`, `stvx128 v.. @0x140..`, lr @308, cr @304, r1 @144, 0 @312, `li r3,0; blr` | 68 |
| longjmp | 0x82FB78D0–0x82FB7BE0 | то же из r7 = r3 (`lfd`, `ld`, `lvx128`), `mtlr` из @308, cr @304, `ld r1` @144, возвращает r4 (или 1, если r4 = 0); если слово @312 ≠ 0 — путь размотки (`bl 0x82FC25B0`, `bl 0x834023C4`) | 430 |

Единственная ссылка на них из данных — запись в `.pdata` (0x822202A0, longjmp). В манифесте:
`setjmp_address` / `longjmp_address`.

## «target not in any function»

| Прогон | Ошибок | Что сделано |
|---|---|---|
| 1 | 46 | 46 записей `{ }`: 18 thunk'ов `lwz r3,8(r3); b` (таблица 0x82396208…), 21 хвостовой вызов, 7 фрагментов листьев |
| 2 | 1 | ещё один thunk той же таблицы (0x823916D0 из 0x823963EC) |
| 3 | 0 | валидация прошла, но 4 «Unresolved conditional branch» на 0x828BF38C → `REX_FATAL` в `sub_828BF39C` |
| 4 | 0 | лист 0x828BF378 целиком: `size = 0xA4` (указатель 0x8204D2BC) |

Ни у целей, ни у источников нет записей `.pdata`: это листья и рукописные thunk'и.

**Шаблон «разрезанный лист».** У листовой функции без `.pdata` есть ранний `blr`, дальше идут ещё блоки, которые
переходят назад в общий хвост. Discovery заканчивает функцию на `blr`, а gap fill начинает новую после него.
Переходы назад становятся «внешними» (`b` — хвостовой вызов в фрагмент; `bc` — `REX_FATAL`), а настоящий вход,
если на него ссылается только vtable, остаётся незарегистрированным. Исправление — весь лист одной функцией с
`size`. Границы берутся обходом всех переходов от входа: должны быть достижимы все слова, ни один переход не
выходит наружу, следующее слово — начало зарегистрированной функции. Так исправлены 0x828BF378, 0x82617468,
0x82618F40, 0x82619320.

## Указатели на код (pointer_fixpoint / pointer_audit)

**Найдено в инструментах из sa2:** диапазон кода sa2 0x82120000–0x82970600 был зашит в `pointer_audit.py`,
`pointer_fixpoint.py` (как тихий fallback: регэксп искал литерал `code_base = 0x…` в `ds2_init.cpp`, а SDK
пишет туда макрос), `pointer_scan.py` и `switch_check.py`. Теперь диапазон берётся из `REX_CODE_BASE/SIZE` в
`ds2_pch.h` (0x82240000–0x83402474), а если его там нет, инструмент падает. Первый audit (с чужим диапазоном)
выброшен.

| Шаг | vtable-like | built in code | Функций |
|---|---|---|---|
| audit до fixpoint | 137 | 50 | 82 947 |
| pointer_fixpoint: проход 1 — 272 кандидата, 249 приняты; проход 2 — новых нет | 3 | 14 | 83 148 |
| три разрезанных листа целиком (выше) | **0** | 14 | 83 147 |

Отклонены fixpoint'ом: 9 фрагментов (читают регистр, неопределённый на входе), 6 хвостовых переходов в тело
функции, 3 выходят за промежуток, 3 без кода, 2 без терминатора.

Оставшиеся 14 «built in code» — не точки входа:
- базы относительных таблиц `switch` (`lis/addi` базы → `lhzx` смещения → `add; mtctr; bctr`), например
  0x829E831C в `sub_829E8240`; их проверяет `switch_check`;
- адреса продолжения для `RtlUnwind` (thunk 0x834023C4), например 0x82FD0C14 в `sub_82FD0BB0`: следующая
  инструкция той же функции.

Не проверено поштучно: все 14 (разобраны 2 характерных; остальные по форме из лога audit).

## Промежутки без функций (find_gaps / gap_fixpoint)

`find_gaps`: 43 761 промежуток, 42 855 из них по 4 байта (выравнивание), кандидатов 8–1024 байт — 906.

`gap_fixpoint.py` пришлось доработать под ds2 и Windows: `codegen.ps1` вместо `codegen.sh`, пути в TOML через
`/`, `codegen_flavor.toml` вместо отсутствующего `perf_overrides.toml`, комментарий-доказательство у каждой
записи (размер и инструкции).

1. **Запуск 1** (`out/gapscan`, проходы 1–4): 400 → 30 → 25 → 26 принятых. Не сходился: `find_gaps` объявляет
   только начало промежутка, а в промежутках лежат цепочки мелких функций (`li r3,7; blr`, `lis/addi r3; blr`,
   пустые `blr` — короткие виртуальные методы). Остановлен после прохода 4.
2. **Нарезка:** кандидат ставится в каждой точке после терминатора (`blr`, `bctr`, безусловный `b`) и нулей
   выравнивания внутри промежутка. **Запуск 2** (`out/gapscan2`): 228 → 75 → 44 → 4 → 0, неподвижная точка.
3. **Регрессия:** последний кодоген дал 26 «Unresolved» и `REX_FATAL` в 13 функциях. Classify пропускал середины
   функций: тела `case` и блоки после раннего `blr`, которые читают «живые» r29/r31 (на входе это допустимо по ABI)
   или начинаются с перехода на общий эпилог `b 0x82FB71xx`. Удалены 11 таких записей (кодоген 6: осталось 14
   «Unresolved» на `bctr` 0x82835A1C), затем ещё 14 — все записи строго внутри функции с `.pdata`, включая
   0x829A3604 от pointer_fixpoint. Это маркер `mr r8,r8`, открывающий SEH `__try`; «указатель» на него — поле begin
   записи SEH-области {0x829A3604, 0x829A369C, 0x829A3614, 0x829A2EE4} в таблице с 0x821C9CF8. Список удалённых с
   причинами — в конце `app/overrides.toml`.
4. **Предохранители в `gap_fixpoint.py`:** кандидат отклоняется, если лежит между источником и целью
   «Unresolved»-перехода пробного кодогена (или перед источником прямого перехода вперёд), а также если лежит строго
   внутри функции с `.pdata`; после настоящего кодогена запуск останавливается, если в `out/codegen.log` есть
   «Unresolved».

Итог (кодоген 7): **0 «Unresolved», 0 `REX_FATAL`**, 83 841 функция; повторные `switch_check` (усечённых,
неверных, пропущенных 0) и `pointer_audit` (vtable-like 0) прежние.

## noreturn

Кандидаты по форме: после `bl X` сразу идут нули выравнивания или начало другой функции.

| Адрес | Что | Доказательство |
|---|---|---|
| 0x82FBF820 | `_CxxThrowException(obj, throwinfo)` | 26 из 35 вызовов — тупик; копирует 32-байтный шаблон ExceptionRecord, кладёт obj/throwinfo, вызывает 0x82995EC0 = `RaiseException` (nargs ограничен 15 → EXCEPTION_RECORD → `RtlRaiseException`) |
| 0x82FB8EC0 | `_invoke_watson` | fail-fast 0xC0000417 (STATUS_INVALID_CRUNTIME_PARAMETER) через 0x82FB8E20, затем `KeBugCheck(30)` (thunk 0x83402054), эпилога нет; 24 вызова |
| 0x82266480 | обёртка, которая заканчивается `bl 0x82FB8EC0` | 7 из 12 вызовов — тупик |

В этом тулчейне noreturn — не ключ генератора, а параметр аудита `tools/read_before_write.py --noreturn=` (для
optimised-режима: какие фрагменты требуют `share_registers`). Семена: `--noreturn=82FBF820,82FB8EC0,82FB78D0`
(throw, `_invoke_watson`, longjmp) → неподвижная точка 40 noreturn-функций. На classic-дереве аудит выдаёт
TOTAL 0 **по построению** (он ищет регистры-локальные, а в classic все регистры `ctx.rN`), поэтому настоящий
прогон — на дереве optimised-режима.

## Не проверено

- Сборка сгенерированного кода (этап 3).
- 8 функций дают больше 1 МБ C++ каждая (0x82D5F1B0, 0x82D6CC30, 0x82D79BD8, 0x82D86B38, 0x82D94AF0 и др.) — это
  только предупреждение генератора, но скажется на времени компиляции.
- 4 оставшихся фрагмента первого прогона (0x8281B4C4, 0x828A865C, 0x828A8774, 0x82CCF38C) корректны в classic;
  вероятно, это такие же разрезанные листья, их входы зарегистрировал pointer_fixpoint.
- Записи из сканирования промежутков вне `.pdata` проверены только автоматикой (classify + отсутствие
  «Unresolved»). Середина листа без `.pdata`, которая не создаёт «Unresolved», отличается от функции только
  в рантайме.
- 237 функций find_gaps не смог измерить.
